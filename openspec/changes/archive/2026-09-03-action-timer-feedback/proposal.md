## Why

牌局已有 30 秒行动超时与自动弃牌/过牌机制，但前端几乎没有把它表达出来：倒计时只有一条 130×8px 的进度条、没有任何秒数文字，玩家无法判断还剩多久；对手的行动状态与已做动作则被 CSS 规则 `.seat:not(.mine) .last/.thinking { display: none }` 全局隐藏，桌面上只剩一个静态金色光圈。结果是玩家主观上感觉「对手可以无限等待」，也看不清谁刚刚做了什么，等待焦虑与误判都由此产生。

机制本身是完好的，缺的只是反馈。补齐反馈的成本远低于其体验收益，且所需数据服务端基本已具备。

## What Changes

- 行动倒计时增加**整秒数字**（`剩 12 秒`），与进度条并存；数字按剩余时间分三阶变色（绿 / 黄 / 红）
- 当前行动者的座位根据剩余时间呈现**颜色递进与脉冲动效**，让「正在等谁、还剩多久」在牌桌上直接可见
- 任意玩家完成动作后，其座位上方**闪现动作提示**（如 `加注 200`、`过牌`、`弃牌`），驻留 3 秒后淡出；提示以浮层呈现，不参与布局，满桌也不会挤压座位
- 解除对非本人座位动作文字的全局隐藏，改为按**人数**（沿用既有 `crowded` 阈值 `>= 7`）分级降级：宽松时显示文字，满桌时退化为颜色与动效
- 服务端在每人视图中把行动截止时间**提升为表级字段**，使所有玩家都能计算当前行动者的剩余时间（此前 `deadline` 仅存在于 `you.act`，只有行动者本人可见）
- 服务端为玩家动作补充**单调递增序号**，供前端判定「是否为新动作」以触发闪现
- 明确不做：不引入震动、不引入音效

## Capabilities

### New Capabilities

- `table-action-timer`: 行动倒计时的可见性契约 —— 剩余时间如何计算、以何精度呈现、颜色阶梯的阈值划分，以及当前行动者在牌桌上的视觉状态
- `table-action-feedback`: 玩家动作的反馈契约 —— 动作提示的触发条件、驻留时长、呈现位置，以及按人数分级的降级规则

### Modified Capabilities

（无。`openspec/specs/` 当前为空，本变更为首个变更，不存在需要修改的既有规格。）

## Impact

**服务端**

- `server/room.js` 的 `stateFor()`：将行动截止时间与行动者标识提升到表级字段；为动作补充递增序号。仅扩展下发视图，不触碰下注、边池、结算等牌局逻辑

**前端**

- `public/js/table.js`：`renderActions()` 增加秒数渲染；`renderSeats()` 增加对手倒计时状态与动作闪现
- `public/table.html`：计时器容器增加秒数节点
- `public/css/table.css`：动作浮层、倒计时数字、脉冲动画的基础样式
- `public/css/app.css`：解除 `.seat:not(.mine)` 对 `.last` / `.thinking` 的隐藏，补充按人数分级的降级规则

**兼容性与既有约束**

- 不改变超时时长（30 秒）、不改变超时后的默认动作（需跟注则弃牌，否则过牌），因此 `tools/edge.js` 的超时断言应持续通过
- 下发字段为新增，旧前端在未更新时仍可正常运行
- 已知限制：服务端广播在同一 tick 内会合并，同 tick 内连续产生的两个动作只会下发最终状态。小盲与大盲的下注属于此类连续动作，因此盲注不作为需要闪现的「动作」处理
