## Why

牌桌当前采用「自适应几何」：`ellipseGeo()` 读取 `.felt` 的实测宽高比推算椭圆半径，`seatWidth()` 再遍历相邻座位反推最大不重叠宽度，写进 CSS 变量 `--seat-w`，所有元素按它取比例。这套方案带来两个玩家可感知的问题：

1. **牌的大小不一致**——`.card.my` 取 `--seat-w * .36`，而对手的 `.card.small` 只取 `* .19`（手机上 `* .17`），对手底牌不到自己的一半，视觉上极不协调，玩家会误以为渲染出错。
2. **界面比例不固定**——同一局在不同窗口尺寸、不同人数下，椭圆的扁平度、座位尺寸、字号全都在变。玩家换设备或缩放窗口后需要重新建立空间记忆，且任何一次几何微调都要在 7 种视口 × 2 种人数下重新验证，维护成本高。

## What Changes

- 牌桌改为**固定 2:1 逻辑画布**（1200×600 CSS 像素）。所有牌桌内元素（椭圆、座位、底牌、头像、公共牌、底池、信息条）在该画布上按固定像素排布，不再随视口变化。
- 画布整体按 `min(可用宽 / 1200, 可用高 / 600)` **等比缩放**后居中显示，多余空间留白（letterbox）。缩放比例统一作用于画布，因此内部所有比例关系恒定。
- **所有底牌统一尺寸**：自己与对手的底牌使用同一规格，不再区分 `.card.my` 与对手的 `.card.small`（座位内）。
- **操作条不参与缩放**：`.action-bar` 留在缩放画布之外，保持当前的响应式行为与可点击尺寸，避免小屏下按钮被缩到无法点击。
- **竖屏显示旋转引导**：竖屏视口下遮盖牌桌区域并提示「请旋转到横屏」，不再尝试在竖屏下压扁椭圆。
- **退休自适应几何**：移除 `ellipseGeo()` / `seatWidth()` / CSS 变量 `--seat-w` 及全部 `calc(var(--seat-w) * k)` 派生尺寸。
- **BREAKING**（内部）：`tools/layout-test.js` 现有约 32 条基于 `--seat-w` 与实测间距的断言全部失效，需按固定画布重写为「缩放后不溢出 + 座位不重叠 + 牌尺寸一致」三类断言。

明确不做：不改变座位的椭圆排布逻辑与「自己固定在左下 135°」的约定；不改变服务端任何协议字段。

## Capabilities

### New Capabilities

- `table-fixed-layout`: 牌桌固定比例布局契约——逻辑画布尺寸与宽高比、等比缩放与居中留白规则、操作条豁免缩放、竖屏旋转引导、牌面尺寸一致性、座位在固定画布上的不重叠保证。

### Modified Capabilities

- `table-action-feedback`: 「动作反馈不挤压座位布局」与「反馈呈现按入座人数分级降级」两条需求的成立依据发生变化——座位尺寸不再由实测间距反推，而是由固定画布与入座人数共同决定，需重述其约束理由并明确浮层反馈在缩放画布内的行为（随画布缩放、不参与布局、不接收指针事件）。

## Impact

- `public/js/table.js`：删除 `ellipseGeo()`、`seatWidth()` 与 `--seat-w` 写入；`renderSeats()` 改为在固定画布坐标系下定位；新增画布缩放计算与 `resize`/`orientationchange` 响应。
- `public/css/table.css`：`.felt` 与座位、牌面尺寸改为固定像素；新增缩放容器样式。
- `public/css/app.css`：移除全部 `calc(var(--seat-w) * k)` 规则与对手牌面的差异化尺寸；移除针对牌桌几何的响应式断点，保留操作条与侧栏的响应式；新增竖屏旋转引导样式。
- `public/table.html`：牌桌区域新增缩放容器层与竖屏引导节点。
- `tools/layout-test.js`、`tools/visual-check.js`：断言与探针改为面向固定画布。
- `README.md`：「座位尺寸是算出来的」一节需改写为固定画布方案。
- 不涉及 `server/` 任何文件，不涉及 WebSocket 协议。
