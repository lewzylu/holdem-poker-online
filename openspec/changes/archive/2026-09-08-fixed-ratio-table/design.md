## Context

当前牌桌的几何完全是运行时算出来的：`ellipseGeo()` 读 `.felt` 实测宽高比推椭圆半径，`seatWidth()` 遍历相邻座位反推最大不重叠宽度写入 `--seat-w`，`app.css` 里约 30 条 `calc(var(--seat-w) * k)` 派生出卡片、头像、字号、下注标签的尺寸。派生系数对本人与对手分别取值（`.card.my` 用 `.36`，对手 `.card.small` 用 `.19`，手机端再降到 `.17`），这是牌大小不一致的直接来源。

约束：

- 牌桌不能依赖仓库外部样式，`table.css` → `app.css` 的加载顺序与优先级关系必须保留。
- 服务端协议不变；本变更只动 `public/` 与 `tools/`。
- 现有 `tools/layout-test.js`（jsdom）与 `tools/visual-check.js`（真实 Chromium × 7 视口）是唯一的布局回归网，二者的探针都读 `--seat-w` 与实测矩形，必须同步改造。

动机见 `proposal.md` 的 Why；行为契约见 `specs/table-fixed-layout/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用一个固定逻辑画布 + 单一缩放系数取代全部运行时几何推算，使布局代码从「反推」退化为「常量」。
- 统一座位内部结构，让本人与对手共用同一套尺寸，从结构上消除牌大小不一致的可能。
- 把「可读性」的责任从缩放画布转移到不缩放的操作条，使小屏退化有确定的兜底。
- 让布局测试从「验证推算是否正确」变为「验证常量是否越界」，断言数量与脆弱度同时下降。

**Non-Goals:**

- 不改变座位沿椭圆分布、本人固定左下 135° 的既有约定。
- 不引入任何构建步骤、CSS 预处理器或第三方布局库（项目当前是零依赖静态资源）。
- 不为竖屏设计独立版式，竖屏只做旋转引导。
- 不改动侧栏（座位表 / 记录 / 聊天）与顶栏的现有响应式行为。

## Decisions

### 决策 1：用 `transform: scale()` 缩放固定尺寸容器

新增两层 DOM：外层 `.table-fit`（填充 `.table-wrap`，`overflow: hidden`，flex 居中）与内层 `.table-canvas`（`width: 1200px; height: 600px`，`transform: scale(var(--tscale)); transform-origin: center`）。`.felt` 及其全部子节点搬入 `.table-canvas`。JS 只做一件事：算出 `--tscale` 并写到 `.table-canvas` 上。

`--tscale = min(fitW / 1200, fitH / 600)`，其中 `fitW`/`fitH` 取 `.table-fit` 的实测尺寸。

选它的理由：`transform` 不触发子树重排，缩放系数变化时不会有回流抖动；缩放对子树是完全统一的，任何内部比例关系在数学上不可能被破坏——这正是本变更要的性质。

考虑过的替代方案：

- **CSS `zoom`**：会真正改变布局盒尺寸并重新做文字排版，同一比例下不同缩放系数可能产生不同的换行与字距，破坏「比例恒定」这一核心保证。
- **全部内部尺寸改用相对单位（`%` / `em` / 容器查询）**：能达到同样效果，但需要把每一处尺寸都换算成相对值，改动面比 `transform` 大一个数量级，且字号缩放仍需引入容器查询单位（`cqw`），浏览器支持面窄于 `transform`。
- **`<canvas>` 或 SVG 重绘牌桌**：可获得最强的比例控制，但会丢掉现有的 DOM 结构、CSS 动画（`seat-breathe`、`af-in`、`dot-pop`）与无障碍语义，代价远超收益。

已知副作用：`transform` 后的元素 `getBoundingClientRect()` 返回的是缩放后的坐标。测试探针需要显式除以 `--tscale` 才能得到逻辑坐标；而「不重叠」这类断言在等比缩放下是尺度不变的，可以直接在缩放后坐标上验证。

### 决策 2：逻辑画布取 1200×600（2:1）

2:1 是横屏设备（16:9 ≈ 1.78、20:9 ≈ 2.22、桌面 16:10 = 1.6）的居中取值，两端留白都不会过分。1200×600 这组绝对数值本身是任意的——缩放后可读性只取决于「字号 ÷ 画布宽度 × 可用宽度」，与画布的绝对数值无关。选 1200 是因为它等于 `app.css` 中 `.felt` 现有的 `max-width`，桌面大屏上 `--tscale` 恰好落在 1 附近，可直接沿用现有的桌面观感作为基线。

### 决策 3：椭圆与座位改为逻辑常量，并统一座位结构

椭圆中心固定在画布 `(600, 300)`，半径 `rx = 460`、`ry = 215`（相对画布为 38.3% / 35.8%）。座位角度沿用 `MY_ANGLE = 0.75π` 起逆时针等分，`renderSeats()` 只保留角度到 `left/top` 百分比的换算，`ellipseGeo()` 与 `seatWidth()` 整体删除，`--seat-w` 及其派生的 `calc()` 规则一并删除。

座位内部结构对所有人统一为「底牌行在上，头像 + 昵称 + 筹码行在下」，尺寸写成固定像素（底牌统一 48×67，头像 34，昵称 13px，筹码 13px）。本人与对手的差异收敛为三点：牌面朝向（明牌 / 牌背）、`.seat.mine` 的金色圈与淡金底、`z-index`。

统一结构而非「保留对手横排、只把牌调大」的理由：后者会让对手座位盒随牌变大而变宽，仍需重新验证 9 人不重叠，且本人与对手的两套 CSS 尺寸表继续并存——牌大小不一致这类问题还会以别的形式复发。统一后 9 人满桌的相邻座位间距（沿椭圆约 240 逻辑像素）远大于座位宽度（约 112），有充足余量。

`.crowded`（≥7 人）阈值保留：它管的是昵称与文字反馈的显隐，与画布缩放无关，见 `specs/table-action-feedback/spec.md` 的 MODIFIED 说明。

### 决策 4：操作条留在画布之外，不做缩放

`.action-bar` 保持在 `.table-main` 里、`.table-fit` 之外，现有的 `@media` 断点规则原样保留。这样小屏下按钮的触控尺寸与倒计时字号都不受 `--tscale` 影响。

这是本变更接受留白的直接代价换来的收益：牌桌可以缩小到看不清，但「还剩几秒、能做什么操作」永远清晰。

### 决策 5：竖屏用 CSS 媒体查询驱动遮罩，JS 不参与

`@media (orientation: portrait)` 下显示 `.rotate-hint` 遮罩并隐藏 `.table-fit` 的内容。不用 JS 判断方向，也不停止任何计时器或网络逻辑——牌局照常进行，超时照常触发（契约见 `specs/table-fixed-layout/spec.md`）。

现有的 `@media (max-width: 640px) and (orientation: portrait)` 那组竖屏版式规则（允许纵向滚动、`.table-wrap { min-height: 46vh }` 等）随之删除。

### 决策 6：缩放系数的更新时机

在 `resize` 与 `orientationchange` 上重算 `--tscale`，并用 `requestAnimationFrame` 合并同一帧内的多次触发。`render()` 里不再需要重算几何，只在首帧与侧栏抽屉开合（会改变 `.table-fit` 宽度）时补一次。

考虑过 `ResizeObserver`：能更精确地捕获容器尺寸变化（包括抽屉动画过程），但会在动画每一帧触发重算，收益有限；先用事件驱动，若发现漏更新再引入。

### 决策 7：测试改造方向

- `tools/layout-test.js`：删除全部基于 `--seat-w` 与实测间距的断言，改为三组：①任意两座位逻辑矩形不重叠（2/6/9 人）；②每个座位逻辑矩形完整落在 1200×600 内；③本人底牌与对手牌背的逻辑尺寸严格相等。
- `tools/visual-check.js`：探针增读 `--tscale`，输出逻辑坐标（实测坐标 ÷ scale）；断言改为「缩放后画布不溢出 `.table-fit`、无滚动条、留白对称」。7 视口 × 2 人数的矩阵保留——它现在验证的是缩放而不是几何推算，用例更少但仍需覆盖两端比例。

## Risks / Trade-offs

- **极小视口下牌桌文字不可读**：640×320 视口在扣掉顶栏与操作条后可用高度约 230，`--tscale ≈ 0.38`，13px 昵称的实际显示只有 5px。→ 这是「比例固定」的必然代价，已由用户明确接受留白与缩放。兜底是决策 4：所有必要的决策信息（提示文字、剩余秒数、可选操作）都在不缩放的操作条上；牌桌上则依赖 `.crowded` 的颜色 / 圆点降级，本就不依赖文字。
- **`transform` 缩放导致小字发虚**：亚像素渲染在非整数缩放下会略微模糊。→ 画布内基础字号取得偏大（≥13 逻辑像素），并避免 1px 边框改用 1.5px 以上；不做整数吸附（会引入留白跳动）。
- **座位常量是硬编码，改动需重新验证不重叠**：过去这个约束由 `seatWidth()` 在运行时保证。→ 由 `layout-test.js` 的不重叠断言在 CI/本地测试里守住；`rx`/`ry`/座位尺寸集中定义为一组命名常量并注明「改这里必须跑 layout-test」。
- **一次性大面积删除 CSS**：`--seat-w` 派生规则遍布 `app.css` 多个断点，漏删会留下 fallback 值（`var(--seat-w, 118px)`）静默生效的死规则。→ 实施时以 `--seat-w` 为关键字全量搜索，删完后再搜一次确认零命中；`render-check.js` / `nav-test.js` 跑通作为兜底。
- **回滚成本**：改动集中在 4 个前端文件 + 2 个测试脚本，无数据迁移、无协议变更。→ 单次 `git revert` 即可回到自适应几何版本。

## Migration Plan

无数据与协议迁移。部署即生效，玩家刷新页面后拿到新版式；进行中的牌局不受影响（服务端未改）。回滚为 revert 单个提交。
