## Context

全部改动位于 `public/` 前端层（table.js / table.css / common.js），数据源（result.seats[].won / revealed[].hand.name、legal.pot、seat chips）均已由服务端下发，无协议变更。实战走查已确认状态广播逐帧自洽，以下设计均建立在"以 state 广播驱动渲染"的既有模型上。

## Goals / Non-Goals

- Goals：结算结果桌面可读（横幅）、节奏提示（紧迫滴答）、筹码反馈（音效/数字弹跳/筹码堆/缩写）
- Non-Goals：下注额位置改到座位前方桌面（九席防重叠余量仅 14px，几何大改风险大，维持既有取舍）；muck 动画、hand history、快捷聊天（P2 暂缓）；任何服务端改动

## Detailed Design

### 1. 获胜横幅（.win-banner）

- **位置**：牌桌画布内、公共牌正上方（`#board` 上方），与 `.table-top`（桌心偏上）错开——横幅放 board 上沿之上、table-top 之下，visual-check 守"不压顶边席位"。
- **数据与时机**：复用结算序号判定（`state.result.seq !== lastAwardSeq`）——结算动画（筹码飞赢家）与横幅同帧出现；`result` 清空（展示期结束）时横幅随之消失，天然无残留。
- **内容**：`result.seats.filter(won>0)` 拼接；`revealed` 匹配出牌型；`result.reason === 'fold'` 时显示「无人摊牌 · 其余人弃牌」。我赢时加 `.mine` 金色高亮类，与既有 toast 并存。
- **平分**：多赢家全列，各显实得金额。

### 2. 展示期提示文案

`renderActions` 的 `t.currentIdx < 0` 分支不再落到「等待发牌…」：`state.result` 存在时显示「下一手即将开始…」。该文案与横幅同生共死，不新增状态。

### 3. 最后 5 秒紧迫提示

- 在既有 `startTimer()` 的 200ms tick 中追加逻辑（不新建 interval）：`secLeft` 从 >5 跨入 ≤5 的整秒跳变时 `playTick()` 一声；同一秒只响一次（记上次响过的秒数）。
- `playTick`：短促方波/正弦 30ms，音量低于轮到提示音。
- 视觉：`.timer` 与 `.seat-sec` 加 `urgent` 态的 CSS 脉冲动画（scale 1→1.15 循环），行动结束/act 消失即停（tick 里已有清除路径）。
- 只挂在**本人**倒计时上：对手的座位倒计时（tickSeats）不加音效。

### 4. 桌心底池筹码堆（.pot-stack）

- 画布内 absolute 浮层，挂于 `.table-top` 的 pot 数字旁；高度/枚数由 pot 金额映射：0 为空、1~200 三枚、~2000 五枚、更高七枚封顶；颜色复用 `.chip-fly` 的金色系，大额混入红/紫点缀（与牌桌筹码语义一致）。
- 数据即 `state.table.pot`，每次 render 重建；pot 为 0（等待期）自然消失。
- 纯装饰浮层（pointer-events:none），不参与布局与防重叠计算；visual-check 加断言：筹码堆不得与公共牌重叠。

### 5. 赢家筹码数字弹跳

renderSeats 重建 innerHTML 会重置动画，故弹跳不能走"重建后加 class"路径：在 `render()` 里对比**上一次**座位筹码值，结算帧（result 存在）的赢家座位在 innerHTML 写入后对其 `.chips` 元素触发 Web Animations API 的 scale 弹跳（一次性 animate，无 class 残留）。

### 6. 筹码金额缩写（common.js 的 `UI.fmt`）

- `UI.fmt`：`n >= 10000` 时输出 `40.6K`（一位小数，去尾零）；其余保持千分位。**`UI.fmt` 是全局唯一格式化出口**（座位筹码、下注额、底池、横幅、日志金额全走它），一处改动全局生效。
- 例外：侧栏「座位」明细表保留精确值（那里是审计语义，非桌面速读语义），单独用 `toLocaleString`。
- 阈值 10,000 的依据：练习房买入 1000、上限 5000，日常金额四位数；五位数出现在长时间赢家中，K 缩写收益开始大于精度损失。GG 同样在高位才缩写。

### 7. 对手下注轻音效

在 `trackActions()` 登记新动作反馈处顺带触发：新反馈的座位非本人、且 `lastAction` 匹配跟注/加注金额模式时 `playBetSound()`（一声 clink，音量取归池声的 2/3）。盲注判定：排除 `kind='blind'` 的日志路径不可行（反馈层拿不到 kind），改为排除「手数开始后的首次动作」不可靠——直接用文案正则 `/跟注|加注/`，盲注文案是「小盲/大盲」，天然不匹配。我自己的动作不响（自己下注自己听，GG 亦如此）。

### 8. 测试

- **ux-test 新增 H 组**（私房打一手弃牌收池 + 一手摊牌）：断言横幅出现、含赢家与金额、摊牌含牌型、展示期 prompt 为「下一手即将开始」、新手开始横幅消失、我赢时高亮类。
- **D 组扩展**：轮到我时把 state 推到 <5s（页面 eval 直接改 deadline 不可行——改为断言 tick 函数行为：向页面注入"剩余 5 秒"的假 state 不可取，改为纯单元式验证：在 jsdom 里直接调用不了闭包……**最终方案**：H 组用私房第二手，B 玩家故意挂 26 秒制造最后 5 秒窗口，轮询页面出现 `urgent-pulse` 类且无 JS 错误即可（jsdom 无音频，声音路径由 D 组既有静默退化断言覆盖）。
- **visual-check**：横幅/筹码堆几何断言（不压顶边席位、不遮公共牌）。
- **回归**：layout-test（横幅浮层若入座位碰撞盒须重跑——设计上不入，pointer-events:none + 不占槽位）。

## Risks / Trade-offs

- **横幅遮挡顶边席位**：横幅在 board 上方约 y∈[240,260] 区域，顶边席位牌顶约在 y=100+，理论不重叠；以 visual-check 实测为准，冲突则下移或缩窄。
- **筹码缩写精度损失**：下注额滑杆精确值不受影响（slider 用整数、非 fmt）；tableChips 显示 9.9K 时玩家对"够不够跟注"的判断由 prompt 的「需跟注 X」精确值兜底。
- **音效密度**：三个新音源（滴答/下注/既有归池）同时活跃时仍须低于 GG 观感——滴答限本人、下注声限额低于归池、归池已有节流；实现后实际对局试听校验。
- **renderSeats 全量重建**：横幅放在 `.table-canvas` 直下（与 #seats 平级），不随座位重建——否则每次广播横幅动画重启。结算帧由 seq 去重，天然只渲染一次。

## 实现偏差记录（与上文设计的差异，均为简化且行为等价）

1. **横幅位置改为公共牌下方（画布 y≈396）**：设计原定 board 上方（y≈240），实现时 visual-check 实测发现 `.table-top` 的 `top:30%` 是 **.felt 内**百分比（画布 y 220~280），与画布 40% 线正面相撞。board 下方与 board 底（364）、底边座位牌顶（433）各留 20px+，是唯一两边不挤的位置，实测 4 视口通过几何断言。
2. **赢家数字弹跳不保存筹码快照**：设计写"对比上一帧座位筹码值"，实现直接复用结算序号（`result.seq`）去重——与结算动画同一判定路径，更简单且天然只触发一次。
3. **弃牌收池横幅不展示牌型**：实现的初版把 `revealed[].hand` 匹配进了横幅，被 H 组测试抓到「无人摊牌（高牌）」自相矛盾——没人摊牌就没有牌型可展示，已改为仅摊牌结算才带牌型括号。
4. **紧迫脉冲挂独立 `t-critical` 档（≤5s）**：CSS 既有档位 `t-urgent` 是 8 秒告警档，与 spec 的"最后 5 秒视觉脉冲"不符；新增 5 秒档挂在操作条倒计时与座位胶囊上，滴答声同阈值。
5. **音效试听（任务 8.5）的局限**：滴答/下注声无法在自动化环境里"听"，以「jsdom 无 AudioContext 时静默退化 + 全程无 JS 错误 + 真实浏览器对局无报错」代偿；音量参数（滴答 0.045 / 下注 0.06 / 归池 0.09）按"层层低于归池"设定，实际听感待人工过审。
