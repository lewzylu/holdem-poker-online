## Context

上一轮变更（`fixed-ratio-table`）已经把牌桌放进一块固定 1200×600 的逻辑画布，整体按 `--tscale` 等比缩放。本次改动完全发生在这块画布**内部**：画布尺寸、缩放机制、操作条外置、竖屏引导等一概不动。

当前画布内的几何是：`.felt` 为 `border-radius: 50%` 的椭圆，`seatPos(k, n)` 用参数方程 `MY_ANGLE - k·(2π/n)` 把**在座玩家**等分到椭圆上，`renderSeats()` 先 `filter(s => s.name)` 再渲染。座位卡为纵向 flex（底牌行 + 头像/昵称/筹码行），高度 112；动作反馈浮层挂在卡片正上方 `bottom: calc(100% + 4px)`。

服务端 `stateFor` **已经在下发全部九个槽位**（空位 `name: null`），前端只是把它们过滤掉了。因此「固定九席 + 空位占位」是纯前端改动，`server/` 零改动。

约束：

- `table.css` → `app.css` 的加载顺序与优先级关系必须保留；牌桌不依赖任何仓库外部样式。
- 「所有底牌尺寸一致」是上一轮刚确立的需求，本次 MUST NOT 破坏——参考图中对手牌更小的做法不采纳。
- `layout-test.js`（jsdom，常量几何）与 `visual-check.js` / `e2e-visual.js`（真实 Chromium）是布局回归网，涉及椭圆与 `.crowded` 的断言必须同步改造。

动机见 `proposal.md` 的 Why；行为契约见 `specs/` 下三份 delta。

## Goals / Non-Goals

**Goals:**

- 用一张九项常量坐标表取代椭圆参数方程，让席位在人员进出时完全稳定。
- 让同侧席位的坐标严格对齐（左两席同 x、右两席同 x、底三席同 y、顶两席同 y），这是圆角长方形相对椭圆的核心收益。
- 把座位的碰撞盒与「是否持牌」解耦，使防重叠结论在牌局任何阶段都一致。
- 移除 `.crowded` 分级机制及其全部关联规则，让反馈在任何人数下都是完整文字。

**Non-Goals:**

- 不改变逻辑画布尺寸（1200×600）、缩放算法、操作条外置与竖屏引导。
- 不改变服务端座位数量、协议字段或任何服务端逻辑。
- 不在牌桌页新增入座交互（空位不可点，坐下仍走大厅）。
- 不改变底牌尺寸，也不为本人与对手引入不同的牌面尺寸。
- 不改动大厅页的九宫格座位选择。

## Decisions

### 决策 1：桌面用圆角长方形而非跑道形

`.felt` 由 `border-radius: 50%` 改为 `border-radius: 120px`，桌面尺寸 900×400，在画布内居中（x 150~1050，y 100~500）。

圆角半径取 120 而**不是** 200（即桌高一半）是关键：取一半就退化成跑道形，左右两侧全是弧，侧边席位只能骑在圆弧上，两个席位的横坐标会随角度漂移。取 120 后左右各留出一段 `y ∈ [220, 380]` 的竖直平边，两席可以贴同一条竖线，横坐标严格相同。

```
   x=150            x=270         x=930            x=1050
     |                |             |                |
     +----------------+-------------+----------------+  y=100  <- 水平直边 x:270~930
    /                                                 \
   |                                                   |        <- 竖直直边 y:220~380
   |                  桌心 (600,300)                    |
   |                                                   |
    \                                                 /
     +----------------+-------------+----------------+  y=500
             桌面 900x400，圆角 r=120
```

考虑过的替代：**跑道形**（`r = H/2`）视觉更柔和，但放弃了同侧对齐这一核心收益；**保留椭圆只换配色**改动最小，但席位仍是环形分布，四角空、直边中段挤，达不到目标观感。

### 决策 2：九项常量坐标表，全部落在直边上

```js
// 画布坐标，(x, y) 为槽位中心
ME: (600, 500)   S1: (430, 500)   S2: (770, 500)   // 底边三席
S6: (500, 100)   S5: (700, 100)                    // 顶边两席
S7: (150, 220)   S8: (150, 380)                    // 左侧两席
S4: (1050, 220)  S3: (1050, 380)                   // 右侧两席
```

分配为「底 3 / 顶 2 / 左 2 / 右 2」而非其他组合，是因为 9 是奇数：要做到本人正下方居中且左右完全镜像，剩下 8 席必须每侧 4 个。底边给 3 席是因为本人必须居中，其两侧各配一席。顶边正中**刻意留空**——那里是底池信息条的位置（现有 `top: 28%`）。

槽位编号按「自本人起顺时针」映射到服务端座位顺序，与现有 `renderSeats()` 的重排逻辑一致，只是目标位置从公式改成查表。

已验证（脚本核算）：九个槽位全部落在直边区段，无一落在圆角弧上；左两席 x 相同、右两席 x 相同、底三席 y 相同、顶两席 y 相同、左右严格镜像。

### 决策 3：碰撞盒 140×101，与是否持牌解耦

座位卡尺寸恒定 140×56（头像 + 昵称 + 筹码横排）。底牌做成卡片外侧的**绝对定位浮层**，向桌心方向探出 45px（牌高 67，其中 22 压在卡片上），因此参与防重叠判定的区域是 **140×101**。

底牌必须绝对定位，理由与上一轮「座位盒高度必须恒定」同源，但这次更强：空位没牌、未发牌没牌、弃牌后没牌，若牌参与布局，同一个槽位在牌局不同阶段会有两种高度，防重叠结论随之摇摆。把牌区固定计入碰撞盒（哪怕当前没牌）即可让结论恒定——这也是 `specs/table-fixed-layout` 里「判定区域不随持牌变化」那条需求的由来。

**实施修正**：牌统一朝**桌心**探出（下半部槽位朝上、上半部朝下），而不是一律朝上——否则顶边席位的牌会顶向画布外缘。碰撞盒随之翻转。这也让最紧的一对从预估的底边 `ME-S1` 变成了侧边 `S3-S4`（同侧上下两席的牌相向而出）。

**压卡量 22px 的下界推导**：侧边同侧两席 y 差 160（竖直直边 220~380 的两端），两张卡各占高度的一半（28），留给两侧牌探出的总空间只有 `160 - 56 = 104`；两席相向而出，故需 `2 × (67 - peek) < 104` ⇒ `peek > 15`。取 22 后余量 14px。想让牌少压卡片，唯一的正路是加高桌面扩出竖直直边，不能只调这个值。

已验证：碰撞盒 140×101 下九席**零重叠**，最紧一对是侧边 `S3-S4`（及镜像 `S7-S8`），余量 **14px**；其次是底边 `ME-S1` / `ME-S2` 的 30px。任何调整都必须重跑 `layout-test`（脚本已加「余量不低于 10px 安全线」断言）。

侧边席位的碰撞盒会探出桌面边界（x=150 处盒子覆盖 80~220），这是刻意的——参考图中侧边座位卡本就骑在桌沿外侧。已验证仍完整落在 1200×600 画布内。

### 决策 4：牌朝桌心，反馈永远在牌的反面

```
下半部槽位                        上半部槽位（.flip）

     [牌][牌]  <- 朝上探出 45      加注 200  <- 反馈翻到卡上方
  +==================+          +==================+
  | (头) 昵称  筹码  |          | (头) 昵称  筹码  |  <- 唯一参与布局的部分
  +==================+          +==================+
     加注 200  <- 反馈在卡下方       [牌][牌]  <- 朝下探出 45
```

现有反馈浮层挂在 `bottom: calc(100% + 4px)`（卡片正上方）。以前不与牌冲突，是因为牌在卡片内部；现在牌搬到卡片外侧，两者会正面相撞。

更要紧的是：废除分级降级后，反馈**不再有退化为圆点的退路**，一旦重叠就是长期遮挡底牌。所以位置必须分开。

**实施修正**：不能简单写死「反馈在卡下」——牌既然随 `.flip` 翻面，反馈就必须跟着翻到**牌的反面**，否则上半部四席的牌与反馈会叠在一起（`visual-check` 在真实浏览器里抓到了这个回归：7 个视口各报 3 处冲突）。座位状态文字（行动中 / 上一步动作）同样遵循这一约定。这条约束已写进 `specs/table-action-feedback` 的两个「分处两侧」场景。

已验证：九席的牌区与反馈条均完整落在画布内，7 视口下无一越界、无一重叠。

### 决策 5：渲染全部九个槽位，空位为不可交互占位

`renderSeats()` 去掉 `filter(s => s.name)`，改为遍历九个槽位；空位渲染为虚线占位，不含昵称、筹码、底牌、下注额与反馈，且不绑定任何点击。

空位不可点是刻意的：牌桌页当前对座位是纯只读，加入座交互需要在牌桌页复用大厅的买入弹窗、处理"牌局进行中能否入座"等一整套状态，与本次「改布局」的意图无关。坐下仍走大厅。

### 决策 6：`.crowded` 整体退休

删除 `renderSeats()` 中的类切换，以及 `app.css` 中挂在它上面的四组规则：隐藏对手昵称、隐藏对手动作文字、隐藏座位秒数、反馈退化为圆点。

理由见 `specs/table-action-feedback` 的 REMOVED 段：座位卡恒定 140×56、槽位间距恒定，两人在座与九人在座时空间完全相同，「人多则挤」的前提消失。

副作用：满席时屏幕上的文字量比现在多（9 个昵称 + 若干反馈同时在场）。这是接受的——它们本就是玩家需要读的信息，此前隐藏只是空间所迫。

### 决策 7：配色调整为墨绿 + 金线

桌布由亮绿径向渐变改为墨绿；边框由 12px 木色改为细金线；座位卡为深色半透明底 + 细边。

`.felt` 的 `border-width` 若改动，必须同步 `table.js` 的 `FELT_BORDER` 常量——座位是相对 `.felt` 内容区（padding box）定位的，两者差一条边框。本次槽位坐标改为直接基于画布，可顺势让座位容器脱离 `.felt` 的 padding box，从而彻底消除这个耦合。

### 决策 8：测试改造方向

- `layout-test.js`：删除椭圆参数方程相关断言，改为读取源码中的槽位常量表并验证：①九席两两不重叠（碰撞盒 140×96，重点守 `ME-S1` 的 30px 余量）②全部落在画布内 ③全部落在直边区段、无一在圆角上 ④四组对齐关系成立 ⑤左右镜像 ⑥页面渲染出的 `left/top` 与常量表一致 ⑦渲染出九个槽位（而非在座人数）⑧空位不含玩家信息。
- `visual-check.js` / `e2e-visual.js`：移除 `crowded` 相关断言；「座位不重叠」的判定对象由在座座位改为九个槽位；新增「底牌在卡上方、反馈在卡下方且不重叠」的断言。

## Risks / Trade-offs

- **底边 30px 余量偏紧**：`ME-S1` / `ME-S2` 是全表最紧的一对。若后续想加宽座位卡或增大底牌，很容易越界。→ 由 `layout-test` 的不重叠断言守住，并在坐标表旁注明「改这里必须跑 layout-test」；余量数值写进注释，让下次调整的人一眼看到预算。
- **满席文字量增加**：废除降级后，九个昵称 + 多条反馈可能同时在屏。→ 接受。若实测过吵，后续可用「反馈错峰」等不依赖人数的手段处理，而不是把降级请回来。
- **空位增加视觉噪音**：空桌时九个虚线框可能显得空洞。→ 占位形态做得克制（低对比度虚线、不填内容），且它传达了「还能坐几人」这个此前完全缺失的信息。
- **侧边碰撞盒探出桌面**：视觉上座位骑在桌沿外，与参考图一致，但若后续把桌面改窄，探出部分可能贴近画布边缘。→ `layout-test` 的「落在画布内」断言覆盖此情形。
- **一次性删除 `.crowded` 全链路**：类名切换在 JS、规则在 CSS 多处。→ 以 `crowded` 为关键字全量搜索，删完再搜一次确认零命中；三套测试脚本跑通作为兜底。
- **回滚成本**：改动集中在 4 个前端文件 + 3 个测试脚本，无数据迁移、无协议变更。→ 单次 revert 即可。

## Migration Plan

无数据与协议迁移。部署即生效，玩家刷新页面后拿到新版式；进行中的牌局不受影响（服务端未改）。回滚为 revert 单个提交。
