# 德州扑克 · 联机版

真人联机、账号体系、资产持久化。**服务端权威**：牌局在服务器里跑，底牌只发给本人，客户端改不了任何东西。

## 最快开始（局域网，零配置）

```bash
cd poker-online
npm install          # 只有一个依赖：ws
npm start            # 默认 3000 端口
```

启动后会打印本机和内网 IP：

```
本机访问：  http://localhost:3000
同网访问：  http://192.168.1.20:3000      ← 把这个发给朋友
```

朋友连同一个 WiFi，浏览器打开这个地址 → 注册账号 → 进大厅 → 创建/加入房间（8 位房间号）→ 坐下买入 → 房主点「开始牌局」。

## 玩法流程

1. **注册/登录**：昵称 + 密码（scrypt 加盐哈希），注册送 5000 筹码，登录状态 30 天免登
2. **大厅**：看到所有房间，点房间号加入，或者自己开一个（可选盲注级别和默认买入）
3. **入座**：点空位 → 填买入额 → 筹码从账号扣到桌上；点自己 → 站起结算回账号
4. **牌局**：四轮下注、边池、摊牌全自动；每人 30 秒操作时间，超时自动弃牌/过牌
5. **补给/离座**：随时补给，牌局中离座会先帮你弃牌、本手结束后把剩余筹码退回账号

## 账号与资产

- 账号数据存在 `data/users.json`（scrypt 哈希 + 随机 token 会话），重启不丢
- 写盘是**先写临时文件再 rename**，写一半崩溃不会损坏账号库
- 登录状态 30 天有效，过期自动失效；会话数量有上限并会清理
- 测试账号**默认不创建**。需要时用 `POKER_SEED=1 npm start` 播种 `test1`/`test2`，
  口令取 `POKER_SEED_PW`，未设置则随机生成并只在启动时打印一次。
  不要在公网环境留下固定弱口令账号。
- 资产分两处：**账号余额**（不在桌上）和**桌上筹码**（买入后冻结在座位上）
- 恒等式：所有人的 `账号余额 + 桌上筹码 + 底池` 始终等于注册赠送总额 —— 端到端测试每次都会校验这条

## 架构

```
poker-online/
  server/
    server.js      HTTP 静态服务 + WebSocket 长连接 + 消息路由
    room.js        房间：座位/买入/开局，驱动 PokerEngine，生成每人独立的视图
    db.js          账号、密码哈希、会话、资产（JSON 持久化）
    poker-core.js  加载牌型与规则核心（从 vendor/ 加载，本地有 ../poker/js 时优先用）
  vendor/          规则核心副本：cards.js / engine.js（ai.js 可选），随仓库自带
  public/          前端三页：登录 / 大厅 / 牌桌
    js/cards.js    牌面渲染与牌型评估（vendor/cards.js 的前端副本）
    css/table.css  牌桌基础样式（布局 / 牌面 / 座位 / 操作条）
    css/app.css    补充样式与响应式，覆盖 table.css
  tools/
    e2e.js         端到端：机器人自动打牌，校验资产守恒
    edge.js        边界：中途离座、掉线重连、补给、超时弃牌
    nav-test.js    页面跳转回归（需 jsdom）
    layout-test.js 座位角度与极端屏幕比例（需 jsdom）
    build-static.js  生成纯静态前端（dist/）
    vendor.js      从 ../poker/js 同步核心逻辑到 vendor/ 与 public/js/
```

`vendor/` 里的副本随仓库提供，克隆下来 `npm install && npm start` 就能跑，
**不依赖任何仓库外部目录**（早期版本会去找兄弟目录 `../poker/`，现在已经不需要）。

**关键设计**：`vendor/engine.js` 是纯逻辑、不碰 DOM 的规则引擎，通过 hooks 与外界交互。联机时把 `requestAction` 换成「等这个玩家的 WebSocket 消息」就完成了升格——规则代码一行没改。联机局没有 AI 座位，所以 `ai.js` 是可选依赖，缺失不影响启动。

**防作弊**：服务端给每个玩家单独生成视图（`stateFor`），底牌字段只在「本人」或「摊牌」时才填充，前端拿不到别人的牌，也无权修改筹码。

## 公网部署

> 沙箱/静态托管只能放**前端页面**，联机还需要一个能跑 Node 进程的**服务端**。

前端静态页已部署（可直接分享）：打开后在登录页点「⚙ 服务器设置」填上你的服务端地址即可，例如 `1.2.3.4:3000` 或 `wss://xxx.onrender.com`。也支持直接用 URL 参数：`https://<静态页>/?s=1.2.3.4:3000`。
注意：静态页是 https 时，服务端必须是 `wss://`（浏览器会拦截混合内容）。

服务端三种上公网的方式：

| 方式 | 怎么做 |
| --- | --- |
| **Docker（推荐）** | `npm run vendor && docker build -t poker . && docker run -d -p 3000:3000 -v poker-data:/app/data poker` |
| **Render.com** | 仓库里已带 `render.yaml`，在 Render 里 New → Blueprint，选这个仓库即可（含 1GB 数据盘） |
| **任意云主机** | 装 Node 18+，`npm install && npm start`，用 nginx 反代并把 `/ws` 升级为 WebSocket |

服务端默认监听 `0.0.0.0:3000`，可用 `PORT` / `HOST` 环境变量覆盖；`GET /healthz` 是健康检查。

其他环境变量：

| 变量 | 作用 |
| --- | --- |
| `POKER_DATA` | 账号库路径，默认 `data/users.json` |
| `POKER_SEED=1` | 播种 `test1`/`test2` 测试账号（默认关闭） |
| `POKER_SEED_PW` | 测试账号口令，未设则随机生成并打印一次 |
| `ALLOW_ORIGIN` | 允许的页面来源（逗号分隔的 host）。留空不校验，方便局域网/反代；公网部署建议配上 |
| `DEBUG_CHIPS=1` | 打印每手牌前后引擎与座位的筹码合计，排查漂移用 |

镜像以非 root 用户运行，数据目录 `/app/data` 已在构建时授权。

```bash

```

`nav-test` / `layout-test` 需要 jsdom（`npm install` 会装上）；
`render-check.js` / `visual-check.js` 需要真实 Chromium（agent-browser CLI），不在 npm 依赖里。

`nav-test.js` 用 jsdom 加载真实页面并拦截 `location.href` 赋值（记录而不真的导航），
从而能断言「这个页面该不该跳、跳几次、跳去哪」。

### 已修的登录态竞态（改这块务必重跑 nav-test）

曾在 `index.html` ↔ `lobby.html` 之间无限跳转，两个原因叠加：

1. **`lobby.js` 在页面加载时同步判断 `Net.isAuthed`** —— 那时 WebSocket 还在握手，`user` 必然是 `null`，
   于是无条件跳回登录页；登录页续期成功又跳回大厅。
   修法：绝不同步判断，只在服务端明确回复 `me`（无 user）或 `needLogin` 时才跳。
2. **`net.js` 里 `me` 请求比 `resume` 认证发得还早** —— `onopen` 先 `emit('conn','online')`，
   页面立刻发 `me`，而服务端此时还没把这条连接关联到用户，回 `user:null`，页面据此判定未登录。
   修法：有 token 时先等 `auth` 回来，再 `goOnline()`。

配套还修了：牌桌页刷新后 `me` 不带房间会被误判「不在房间」（服务端改为反查用户实际所在房间）；
牌局进行中点「返回大厅」会被反复拽回牌桌（用 `sessionStorage` 标记主动返回）。

## 牌桌布局与移动端

**牌桌是固定九席**：底 3 / 右 2 / 顶 2 / 左 2，坐标是一张写死的常量表，与在座人数无关，
没人坐的槽位渲染成虚线占位（不可点，入座仍在大厅完成）。
**自己永远固定在底边正中**（0 号槽位），其余玩家自本人起顺时针环绕。
牌局中座位不会因为别人进出而换位，看牌位置固定，手机上能形成肌肉记忆。
所有人的两张底牌**横向并排、尺寸相同**，本人座位有淡金底色以便一眼定位。

牌桌顶部信息（阶段 / 底池 / 房间号+盲注）合成一行胶囊，公共牌只渲染已发出的牌（不留灰色占位）。

### 固定比例画布

牌桌的尺寸是**写死的**，不是算出来的：全部桌面元素排布在一块固定 **1200×600（2:1）** 的逻辑画布上，
整体按 `min(可用宽/1200, 可用高/600)` **等比缩放**后居中，多余空间留白。

```
.table-wrap            可用矩形
└─ .table-fit          overflow:hidden
   └─ .table-canvas    width:1200px height:600px
                       transform: translate(-50%,-50%) scale(var(--tscale))
      ├─ .felt → .table-top / .board / .waiting
      └─ .seats        铺满整块画布（不是 .felt 的内容区）
```

`table.js` 的 `fitCanvas()` 只做一件事：算出 `--tscale` 写到 `.table-canvas` 上
（`resize` / `orientationchange` / 侧栏抽屉开合时用 `requestAnimationFrame` 合并重算）。
用 `transform` 而不是改尺寸：它不参与布局、不重排子树、不重新做文字排版，
所以画布内的比例关系在数学上不可能被破坏。于是：

- **所有底牌一样大**（统一 `.card.small` = 48×67），本人与对手的区分只靠牌面朝向和座位高亮
- 任何视口下「牌 ÷ 桌」「座位相对位置」都是同一个数，换设备不用重建空间记忆
- **操作条不在画布里**，不跟着 `--tscale` 缩小 —— 牌桌可以缩到看不清，但「还剩几秒、能做什么」永远清晰
- **不再按人数分级降级**（`.crowded` 已废除）。九席是固定的，画布上的余量与在座人数无关，
  所以满席也不需要隐藏昵称、也不需要把动作反馈退化成圆点 —— 常量表已经保证了 9 席不重叠
- **竖屏显示旋转引导**（纯 CSS `@media (orientation: portrait)`，JS 不判断方向），
  牌局照常进行、倒计时照常走、超时照常触发

#### 为什么是圆角长方形而不是椭圆

桌面是画布内居中的 **900×400、圆角 120** 的圆角长方形（`.felt`）。
圆角必须**小于桌高一半**（120 < 200）：取一半就退化成跑道形，左右全是圆弧，
侧边席位只能骑在弧上、横坐标随角度漂移，做不出「同侧两席严格对齐」。
取 120 后得到直边区段 —— 水平 `x ∈ [270, 930]`、竖直 `y ∈ [220, 380]`，
九个槽位全部落在直边上，同侧席位能贴同一条线。

槽位表在 `table.js` 的 `SLOTS`（本人 600,500；底边 430/770,500；右 1050,220/380；
顶 500/700,100；左 150,220/380），左右严格镜像，**顶边正中刻意留空**给底池信息条。

**碰撞盒与「是否持牌」解耦**：参与防重叠判定的永远是「座位卡 140×56 + 牌向桌心探出 45」= **140×101**，
和当前有没有牌无关 —— 否则同一个槽位在牌局不同阶段有两种高度，防重叠结论会跟着摇摆。

「9 席不重叠」只由这张表 + 几个 CSS 尺寸保证，**改动它们必须重跑 `node tools/layout-test.js`**。
余量很紧：最紧的是侧边上下两席（牌相向而出）只剩 **14px**，其次底边 30px。

```bash
node tools/layout-test.js     # 常量几何（九席不重叠/落在直边/镜像）+ 页面定位一致性，无需浏览器
node tools/visual-check.js    # 真实 Chromium 量缩放（需 agent-browser，会先手动进一局）
node tools/render-check.js    # 真实 Chromium：底牌横排、日志行飘位、公共牌占位、牌面等大
node tools/e2e-visual.js      # 真实 Chromium：三视口 + 竖屏引导 + 跨视口比例恒定 + 控制台报错
node tools/bots.js 4          # 起机器人开一局，留一个位置给浏览器玩家
node tools/fill-room.js <房间号> 5   # 往已有房间补机器人，凑满桌做 9 人验证
```

### 踩过的坑

- `.layout` 用 grid 但没给 `grid-template-rows`，行高取 auto 时**不会拉伸填满容器**，
  牌桌的 `height:100%` 会塌成只剩边框的高度（横屏手机上牌桌只有 16px）。必须显式写 `minmax(0,1fr)`。
- 末尾的 `@media (max-width:1000px)` 里如果有 `height:auto`，会覆盖掉前面所有高度声明，
  导致矮屏规则失效。改成 `@media (max-width:1000px) and (min-height:601px)`；
  并且那里必须给 `.table-wrap` 一个 `min-height`，否则 `flex:1` 在 auto 高度下解析成 0，
  `fitCanvas()` 就量不到可用区域。
- **日志行的 class 不能直接用日志类型名**。发牌日志的 kind 是 `board`，而公共牌容器也叫
  `.board`（带 `position:absolute; left:50%; top:42%`），于是「河牌：♦A ♣A …」这行日志会
  脱离文档流、飘到页面正中间。日志统一改用 `ln-<kind>` 前缀，并在 `.log div` 上加了
  `position:static !important` 兜底。
- **两张底牌必须包进 `.hole`**。`.seat` 本身是纵向 flex，直接塞两张 `.card` 会变成上下堆叠。
- **`#seats` 必须是画布的直接子节点，不能挂在 `.felt` 里**。槽位坐标是画布坐标，
  一旦定位父级变成 `.felt`，九席会整体偏移一个 `.felt` 的 left/top（改造中真实踩到过，
  偏了 68px 还看着「差不多对」）。这样也顺带和 `.felt` 的边框宽度彻底解耦。
- **座位盒的高度必须恒定**。行动状态文字、下注额、徽章、动作反馈全部做成绝对定位浮层：
  一旦它们参与布局，座位就会随牌局状态忽高忽低，画布上的防重叠常量立刻失效。
- **底牌浮层的 `z-index` 不能用 `-1`**。想让牌垫在昵称筹码后面，负值会让它沉到画布背景层之下、
  连牌都看不见。正确分层是牌 `1` < 卡片 `2` < 卡片内容 `.info` `3`。
- **底牌水平方向靠左偏置，不能居中**。两张牌叠压后共 82px、卡片只有 140px，居中的话牌正好压在
  昵称与筹码上；靠左之后只挡住头像那一侧（圆形色块被挡一点无妨）。
- **两张底牌是叠压 14px 的，且下层那张的内容必须左移避让**。叠压是为了把牌区横向占用从 100
  收到 82，但点数和花色是居中排版的，实测「10」这种两位数点数的右边缘距上层牌左沿只剩
  0.8px —— 靠 `translateX(-7px)` 把下层内容推开，余量才回到约 11px。叠压量 14 是上限，
  再大就压掉读数。也别改成旋转扇形：牌 48×67 旋 6° 纵向多出约 4.6px，侧边只有 14px 余量，一转就跌破安全线。
- **座位卡内容不是垂直居中，而是用 padding 给牌区让位**。牌压住卡顶 22px，而 30px 的头像
  居中时占 13~43、昵称占 21~35，都会伸进牌区，白牌上衬白字对比度很差（`z-index` 保证画在
  上面，所以是观感问题不是可读性问题）。`.info` 铺满卡片高度 + `padding-top: var(--hole-peek)`，
  padding 侧随 `.flip` 翻转。相应地 `.seat` 必须是 `align-items: stretch` 而非 `center`，
  否则 `.info` 只按内容高度收缩、吃不到 padding；`.empty-tag` 则要自己居中。
- **测「牌有没有压住卡片内容」必须量内容元素，不能量 `.info`**。`.info` 铺满整个卡片、
  靠 padding 让位，它的盒子与牌区必然交叠，拿它判定会永远失败（加断言时真实踩到过）。
- **跑完竖屏用例的脚本必须把视口复位到横屏**。`visual-check` / `e2e-visual` 的最后一档都是
  竖屏，而竖屏下 `.table-fit` 是 `display:none`，接着跑 `render-check` 会量到一堆 0、
  断言拿 0 和 0 比。两个脚本结尾都补了复位，`render-check` 也加了可见性守卫。
- **牌和反馈占哪一侧要跟着 `.flip` 翻**。牌统一朝**桌心**探出（下半部朝上、上半部朝下），
  反馈与状态文字则永远在牌的反面。只写死「反馈在卡下方」会让上半部四席的牌与反馈叠在一起 ——
  改造中真实踩到过，`visual-check.js` 现在两个方向都断言。
- **`--hole-peek`（牌压住卡片的高度）不能凭感觉调小**。侧边同侧两席 y 差 160、两张卡各占 28，
  留给牌探出的总空间只有 104，而两席相向而出，所以必须 `2 × (67 - peek) < 104` 即 `peek > 15`。
  想让牌少压卡片，唯一的正路是**加高桌面**扩出竖直直边，不是改这个值。
- **牌桌中央的元素要躲开顶部座位**。信息条原先在 `top:7%`，正好被顶边席位的牌背压住 ——
  改造中真实踩到过。现在信息条 `top:30%`、公共牌 `top:50%`，
  并由 `visual-check.js` 的遮挡断言守住。另外 `top` 只能写在 `table.css` 一处：
  `app.css` 里再写一个会覆盖掉它。
- `transform: scale()` 之后 `getBoundingClientRect()` 返回的是**缩放后**的坐标。
  要拿逻辑坐标得除以 `--tscale`；不过「两个矩形是否重叠」在等比缩放下是尺度不变的，可以直接判。
- 写视口测试用例时注意**竖屏会隐藏整个牌桌**（旋转引导），量出来的矩形全是 0，
  断言会「无意义地通过」。横屏用例必须宽 > 高，并先断言画布可见。
- **旁观（未入座）时没有「本人」可作基准**，直接拿服务端座位号当槽位号会让少数几人
  全落在编号相邻的槽位、挤在同一条桌边。改用 `round(j * 9 / n)` 沿九席等距摊开，
  9 人时自然退化成一一对应。
